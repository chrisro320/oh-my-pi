# Orca 图像会话后台保真与 Android 卡顿

## Goal

修复两项用户可观察的问题：桌面切换终端后图片变空白，以及 Android Orca 仅含图终端会话明显卡顿、接近闪退。不能以局部测试通过替代完整会话生命周期或 Android 实机验收。

## Background

- 用户原话：“图片应该是没丢，像是临时的渲染问题”；切走再切回缺图，隐藏侧栏后恢复。
- 用户原话：“带有 image 的那个终端，我用 orca 手机端看特别卡，几乎直接会闪退”；已确认 Android，并补充“是带图终端会话卡，普通的不会卡”。尚未确定卡顿发生于打开、滚动还是持续输出。
- 用户选择“后台继续处理，保住图片”，并说明“我配置足够好”。接受为保真增加后台解析成本；不要求改造完整图像快照。
- 2026-09-24 用户明确要求创建本 Trellis 任务，覆盖建任务之前已有的调查及未提交候选。
- 任务保存在当前 `omp-move`；当前产品代码修改归属 `/home/chris/orca/projects/orca-update-patch`。两仓库不得混交提交。
- 基线：Orca 1.4.210，已部署图片修补包 1.9.2；生产 ASAR SHA-256 为 `52a511a2df9b40b65f93d310159258b9e13f33c3be59e1dd9701650016f107ec`。本批候选仅进入隔离程序，未部署生产。

## Requirements

### R1 — 桌面后台输出保持图形状态（高优先级）

含图会话切到后台后仍接收并解析完整原始输出。切回时不得用不含图片资源和位置的文字快照替代现有图形状态。

证据：原生隔离 Orca + 真实 OMP，前台 3 图，切到另一个项目后再产生 3 图。旧版切回执行 `ESC[2J` / `ESC[3J` 后重播不带图形传输的文字，图片存储由 3 变 0。侧栏改变列数后 OMP 重传，图片恢复。见 `research/desktop-before.json`、`desktop-before.png`。

源码锚点：`terminal-pane.js:31953-32042,35517-35524,35681-35762,36454-36460`；`main.js:46725-46767,76653-76678,76711-76738,80316-80345`。这些是 `research/evidence.md` 指定版本的格式化 ASAR 映射，不是可直接修改的产品源文件。

### R2 — 窗格回收、重建和再次进入仍保真（高优先级）

后台连续解析的状态必须跨过 Orca 的窗格卸载/回收/重建边界。不能仅保证原 Terminal 对象尚存的短时间切换。

候选已通过短时间切回：6 图、6 次传输、111978 字符，返回前后没有新增输出。但在继续切换其他窗格后，原 Terminal 被替换，新可见窗格仅恢复文字、0 图，故候选未通过最终验收。见 `research/desktop-short-return-pass.json`、`desktop-eviction-failure.json`、`desktop-eviction-failure.png`。

### R3 — Android 含图会话不再异常卡顿（高优先级）

以同一 Android 客户端上的普通会话为对照，修复含图会话打开、持续使用或滚动时的异常卡顿/崩溃风险。修复必须落在实际手机所使用的资产、原生桥或服务端链路，不能把桌面插件补丁视作手机补丁。

已确认的代码边界：`out/mobile-web` 是独立 Expo 移动资产；其当前 session bundle 终端只加载 WebGL 和 Unicode11，未加载桌面 ImageAddon。浏览器 screencast 的 JPEG/base64 帧不是终端帧。见 `research/evidence.md`。

本机同源 xterm 引擎探针累计处理 13012391 字符、267 次写入，队列清空，最大单次回调耗时约 8.2 ms。它未经过 Android 原生壳、`orcaBridge` 或 `terminal.subscribe`，因此只能限定机制假设，不能作为 R3 通过证据。手机完整链路根因尚未确定。

### R4 — 可重放部署、回滚及数据安全

- 在 Orca 补丁仓库维护源文件，经版本与完整哈希门禁部署；禁止裸改生产源码。
- 保留用户选择的 64 MB 配置与 `tui.maxInlineImages: 0`；不靠加缓存、删历史、禁图片、重复重传或轮询掩盖问题。
- 保留现有可见性与后台 GPU 暂停逻辑，不主动重启生产 Orca/OMP。
- 保护既有 Claude polling 禁用补丁、凭证、agent.db、会话数据和配对状态。
- 先验证所有目标，再原子替换；只接纳已固定哈希的历史修补版本；保留内容寻址备份并可精确还原。

## Acceptance Criteria

- [ ] AC1 / R1：同一旧版复现失败、修补版通过；前台已有图片，后台产生新图，切回后实际 DOM canvas 有正确图像，无侧栏缩放、显式 `refresh()`、滚动补救或 OMP 重传。
- [ ] AC2 / R2：经过普通切换、跨项目切换、窗格实际回收/重建，再进入含图会话，旧图和后台新图均正确；记录 Terminal 身份及实际可见画布，不只数缓存项。
- [ ] AC3 / R1+R2：首次图片在后台产生也保留；至少 40 张混合尺寸图片完整传输、正确预留行、可视区域完整显示，并检查首/中/末历史图片。当前原图压力探针只证明 40 次传输和约 12.5 MB 字节保留，其旧版 emit 脚本在底行未预留图片高度，不能认定完整视觉验收。
- [ ] AC4 / R3：确认 Android 当前实际资产版本与接收路径；在真实故障场景下取修复前后对照，含图会话不再异常卡顿/闪退，普通会话无回退。无实机证据时不得勾选。
- [ ] AC5 / R4：原有图片、历史预算、分片与 idle 模式门禁不回退；补丁 status/升级/幂等/拒绝未知/精确回滚/非目标保护通过；普通用户对 root-owned pending ASAR 仅 status，无写入。
- [ ] AC6 / R4：包装版本、现有文档和可机检 spec 同步；安装包及生产部署有明确证据，冷启动验证与生效前提明确；不覆盖其他工作。

## Out of Scope

- 重做完整 headless 图像快照体系：用户选择保持后台解析的路线。
- 仅为本任务给手机新增完整 Kitty/SIXEL 图片显示功能，或更改手机安全/配对权限。
- 升级 Orca/OMP、修改模型、数据库、认证或上下文审计扩展。
- 自动提交、推送或重启用户工作中的程序。
