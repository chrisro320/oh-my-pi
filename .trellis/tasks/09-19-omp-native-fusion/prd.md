# OMP 原生 Fusion 直接接入

## Goal

Make Devin Fusion work directly inside OMP: the selected lead and persistent sidekick perform native Fusion handoffs while OMP retains its interface, tools, permissions, and session history. Success means an actual lead → sidekick → lead workflow, not merely a successful lead response.

## Background and confirmed evidence

The user reports reliable native Devin Fusion and repeated OMP failures for `fusion-gpt-5-6-sol-xhigh-sidekick-swe-2-high`. That report is accepted as ground truth. Native CLI 3000.10.31 and installed OMP 18.2.3 were inspected. No Fusion production edits have been made.

Evidence is pinned in `research/native-evidence.zip`, with hashes in `research/evidence-manifest.json` and interpretations in `research/native-protocol.md`. Native requests were generated by the real executable in network-isolated namespaces with synthetic credentials and controlled server responses. These establish client behavior, not live assignment decisions, billing, or model quality.

## Requirements

- **R1 — Native direct routing (P0).** Resolve the Fusion selection through native assignment and preserve returned routing identity. Current discovery excludes harness-backed routers at `pi-catalog/src/discovery/devin.ts:453-460`; `pi-ai/src/providers/devin.ts:259-267` consequently sends the composite directly. Native internal handoffs also emit protobuf field 6, absent from `pi-catalog/src/discovery/devin-proto.ts:1157-1169`. Correct the source behavior; do not hardcode the lead UID as a fallback.
- **R2 — Persistent native sidekick (P0).** Exactly one logical sidekick per Fusion session. Support blocking and background handoffs, reading results, and updating an active handoff. Retain prior child history between completed handoffs; distinguish an update to a running handoff from starting the next handoff.
- **R3 — OMP tools and permissions (P0).** Both roles use OMP tool execution and permission boundaries. Fusion's `sidekick` and `read_subagent` have registered session-owned handlers, not unresolved generic tool names. An active child read completes before its result and lead update are sent onward. Background work gains no implicit approvals. Ordinary models do not receive Fusion-only tools.
- **R4 — Lifecycle and delivery (P0).** Cancellation invalidates the affected handoff and suppresses late success. Nonretryable child errors reach the lead with their original meaning. Completion reports are delivered once per handoff. Session disposal/model switching releases active resources without cross-session delivery. Completed child history survives process restart; interrupted in-flight work is recorded honestly rather than reported as completed or silently re-executed.
- **R5 — Identity, replay, and context (P1).** Keep stable local session/handoff identity separate from wire message IDs. Preserve tool-call/result correlation and role-specific cascade/trajectory ownership. Restore child state along the selected OMP session branch and reset boundary. Respect existing context limits/compaction and preserve required thinking signatures; do not bypass compression or erase child history to obtain a passing smoke.
- **R6 — Compatible patch delivery (P1).** Deliver through the canonical repository patch chain and its supported-version gates; preserve current Devin auth, signature replay, and non-Fusion behavior. Never edit the global runtime as the source of truth. Existing user work and other migration tasks stay untouched.

## Acceptance Criteria

- [ ] **AC1 / R1:** Public OMP discovery/provider execution emits Fusion `AssignModel` followed by the returned UID/JWT on the same lead cascade; the unrepaired behavior fails this assertion. Internal assignment independently verifies field 6 bytes, distinct from field 5.
- [ ] **AC2 / R2:** Real OMP agent execution completes lead → child tool → lead, then a second handoff retains the previous child brief and reply. Assignment/model roles follow controlled responses rather than parsing model names.
- [ ] **AC3 / R2–R3:** Barrier-controlled background execution lets the lead continue; an active-handoff update reaches the same child cascade without a second assignment. Completed-handoff reentry retains history and uses the native observed lifecycle.
- [ ] **AC4 / R3:** A real permitted local read is in progress before a lead update; its output and correlated tool result survive before the update in the next child request. Approval-required background operations are refused without approval. No duplicated execution.
- [ ] **AC5 / R4:** Cancel during a held child response; release a late success; OMP reports cancellation and does not inject the late success. A nonretryable child failure is surfaced once and the lead can continue.
- [ ] **AC6 / R4–R5:** Restart OMP after a completed handoff and restore the same session: old child brief/reply plus the new brief appear together with valid tool associations. Reset, branch navigation, model switch, and session disposal do not leak child state or completions.
- [ ] **AC7 / R5–R6:** Non-Fusion Devin routing/auth/signature gates remain green. Child history respects the configured context budget; no duplicate reports or stale completions after replay/compaction. Public declarations match any changed interface.
- [ ] **AC8 / R6:** Generate from a verified supported-version sandbox, replay the exact active patch chain, reverse/reapply cleanly, import the real SDK, and launch the actual OMP source CLI. Verify deployment/runtime parity only at the authorized deployment step.
- [ ] **AC9 / R1–R6:** After explicit approval for the exact live smoke, run the selected Fusion through OMP with an actual sidekick tool operation and a follow-up handoff. Report exercised behavior separately from fixture verification. Full acceptance remains open until this succeeds.

## Out of Scope

- ACP wrapping, launching Devin CLI in production, or substituting OMP task/hub orchestration for Fusion.
- Replacing OMP's UI/tool suite with Devin's tools, or building a general-purpose multi-agent platform.
- Upgrading OMP, modifying other active migration tasks, or supporting unverified OMP versions by silent fallback.
- Credential migration, billing assumptions, unrelated metadata cleanup, or claims of server cache equivalence from synthetic traffic.
