OMP 18.18.0 升級計畫

把現在用的客製 omp 18.16.0 升到上游 18.18.0：自訂功能不默默消失，prompt cache、壓縮和 Anthropic 登入都不被破壞。計畫已經過四輪獨立審查；實作、安裝、上線各自另外經你批准。

現況

  • 你現在用的是客製 18.16.0，上面疊了 26 組自訂改動，共 62 項自訂功能。
  • 上游已經出到 18.18.0，帶來子代理背景執行緒、Anthropic 連續對話等新功能。
  • 把現有改動直接套到 18.18.0，有一半套不上。
    • 退役後剩 24 組，其中 12 組失敗，共 67 處要重寫。
    • 另有 5 組雖然套得上，但意思已經錯了，例如第一次呼叫 Anthropic 就會當掉。
  • 18.16.0 已經修好「跨午夜後日期讓整段對話暫存失效」，這個修正會保留。

難點

  • 新功能和我們的改動互相衝突，但你不接受「為了穩定把新功能全部關掉」。
    • 原則：預設採用上游新功能，只有修不好時才暫時關閉，並寫下重新開啟的條件。
  • 開啟背景執行緒後，有些改動不會當機，卻會默默多花錢或讓暫存接不上。
    • 例如多條執行緒同時更新登入憑證，可能讓 Anthropic 登入失效。
  • Anthropic 連續對話的接續點，可能被暖機重送和壓縮摘要搶走。
  • 上游把 Codex 的連線整個重寫，我們的壓縮鏈改動要重新寫。
  • 你正在用的 omp 不能被碰壞，所以所有驗證都要在隔離環境做。

決定

鎖定 18.18.0，之後的 18.18.x 不追。 本人已選

18.17.0 沒有 18.18.0 對背景子代理當機的修正，兩版工作量幾乎一樣。

退役 3 項少用功能，保留 Hindsight 與 Devin。 本人已選

退役：Command Code DeepSeek 模型設定、Ollama Cloud 額度顯示、StepFun step plan。

StepFun step plan 退役後就不能用了，上游沒有對應功能。

新功能預設開啟，修不好才暫時關閉。 本人已選

子代理背景執行緒預設 4 條；同時跑 9 個以上子代理時才會用到。

Anthropic 連續對話採用，衝突在本地修正；修不好時可關閉。

只有符合條件時才會用：官方 Anthropic API、Claude 4.5 以上、一般對話。

暖機重送和壓縮摘要刻意不走連續對話，避免搶走接續點。

你實際連到的是不是官方 API，要到實作時在隔離環境確認。

Codex 回答長度採上游預設「短」。

修跨午夜壓縮，不修顧問換帳號。 本人已選

你沒有用多個帳號跑顧問，所以那個情況不會發生。

每一步都先在隔離環境通過檢查才往下走。

每個檢查都配一份故意弄壞的對照，弄壞時必須亮紅燈。

正在用的 omp、資料庫、憑證和暫存都不碰。

實作分 10 步，另開任務逐步進行。

下一步怎麼走？

建架構與退役 → 照搬重套 → 對話與續接 → 壓縮鏈 → 登入

Anthropic 連續對話 → 背景執行緒全測 → 外掛與原生 → 總驗收 → 你親手驗收

預期成果

  • 升級後，除了你選擇退役的 3 項，原本的自訂功能都還在。
  • 開新對話、續接舊對話、壓縮之後，暫存照常接上，不會突然用全價重送整段對話。
  • 跨過午夜後壓縮，也照樣沿用暫存。
  • 升級後 Anthropic 登入照常可用，開著背景執行緒也不會失效，不用重新登入。
  • 一次派出很多子代理時，它們會分到背景執行緒平行跑。
  • 在官方 Anthropic API 上用 Claude 4.5 以上時，符合條件的一般對話每輪只送新訊息，回應延遲較低；上游表示費用不變。
    • 暖機重送和壓縮摘要不走連續對話，照舊送完整內容。
    • 實際連線路線還沒驗證；若某項檢查修不好，會先關閉這個功能上線，並寫下重新開啟的條件。
  • Codex 的回答預設比較短，想要長一點仍可在設定改回。
  • 上線前，你會在隔離環境親手驗收畫面、Escape 和壓縮。

分工

    • 第一步（建架構、退役 3 項）交一個 task worker 做，main 驗收。
  • task照搬重套的補丁依共用檔案分 3–4 組平行做，共用檔案的照順序由同一人做。
  • taskex壓縮鏈和閒置暖機各由一位負責，這兩塊最容易改錯。
    • 背景執行緒全測也由 taskex 負責。
  • reviewer上線前做一次獨立審查。
