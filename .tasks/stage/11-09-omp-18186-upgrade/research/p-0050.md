### Cause (file:line, 18.18.0 tree and unchanged in 18.18.6)

1. `pi-tui/src/overlays/session-selector.ts:2004` (18.18.6: `:1982`) —
   `SessionSelectorComponent.render()` emits the panel's top border, its
   children (`Spacer`, message container, content slot = `SessionList`) and the
   footer. **No preview pane exists on the ANSI render path.**
2. The only preview is the native one:
   - `sessionPreview()` at `:174` (18.18.6: `:169`) builds the title, fact grid
     and conversation nodes;
   - `#describePicker()` at `:2142` (18.18.6: `:2113`) passes
     `layout: "cards", preview: "side"` and `#previewFor(...)`;
   - `#previewFor()` at `:2228` (18.18.6: `:2206`) rebuilds it on selection settle;
   - `describe()` at `:2077` (18.18.6: `:2055`) returns that picker **only when
     `cx.supports("picker")`**, i.e. only while a Tern Surface Protocol surface
     is live.
3. `describe()` is consulted instead of `render()` only by the native backend,
   which starts from a `hello` handshake and an optimistic start keyed on
   `TERM_PROGRAM=tern` (`pi-tui/src/terminal.ts:1116` `tspExpected` →
   `isTernPane`; `pi-tui/src/tui.ts:1797` constructs `NativeBackend` after the
   hello). A plain terminal, tmux, or a Tern build that does not answer keeps
   the ANSI path.
4. `SessionList.handleInput` has **no Space binding**: printable keys fall
   through to the search `Input`, so Space types a space into an empty query
   (invisible), which is exactly what the user experienced.

Measured probe of the native route (same pty, `TERM_PROGRAM=tern`, no TSP
responder). omp sends the hello and optimistically opens surfaces, then closes
them and repaints in ANSI — the picker still shows no preview:


So: outside a live TSP surface there is no preview code path at all, and no key
opens one. That is the whole defect.

## 2. Implementation on pristine 18.18.6

Five files (all 0050-owned), NM-root relative:

| file | change |
|---|---|
| `pi-coding-agent/src/session/session-listing.ts` | `SessionInfo.lastModel` + `deriveLastModel()` (ported from the 18.18.0 family); new `SessionInfo.lastAnswer` + `deriveLastAnswer()` reading the existing 32 KB tail window |
| `pi-coding-agent/dist/types/session/session-listing.d.ts` | mirror of both fields |
| `pi-tui/src/overlays/session-selector.ts` | `SessionSelectorEntry.lastModel`/`lastAnswer`; `shortenModelName()` + last-model column in both row renderers; new `SessionPreviewView`; Space/Esc/Space/Enter/Ctrl+C/scroll input routing; `Space preview` footer hint; `SessionList.searchQuery` getter |
| `pi-tui/dist/types/overlays/session-selector.d.ts` | mirror of both fields |
| `pi-tui/src/overlays/session-info-overlay.ts` | retained 0050 predicate `path !== "In-memory"` |

Behaviour:

- **Data, no transcript read.** The preview text comes from the listing that
  already ran: `firstMessage` (4 KB prefix) and the new `lastAnswer` (newest
  assistant text in the 32 KB tail window; ≤ 4000 chars kept; falls back to the
  tail of `allMessagesText` for listings without the tail read). Selecting a
  session therefore costs one stat + the windows the picker already reads, and
  no file is opened beyond the picker's own scan.
- **Space** opens the preview only when the search query is empty and a session
  is selected; with a non-empty query the key reaches the search input and types
  a space (unchanged).
- **Preview keys**: `Esc` or `Space` back (cursor and query untouched — the
  list is never re-created, it is re-mounted from the same instance), `Enter`
  resumes the previewed session through the same `resumeSelected()` path as the
  list, `Ctrl+C` exits like the list, `↑`/`↓`/`PgUp`/`PgDn`/`Home`/`End` scroll.
  Every other key is swallowed, so nothing can leak into the search box.
- **Viewport fit.** The view renders exactly `terminalRows − 6` lines (top
  border, spacer, footer's 4 rows are the chrome), so the overlay frame is never
  taller than the viewport; a taller frame is what pushes the panel's top rows
  into scrollback (the same hazard the delete dialog documents at issue #3283).
  Longer conversations scroll inside that window with a `lines a-b of N` row.
- **Text safety.** Session bytes are forked through `previewText()`: tabs
  expanded, CRs normalised to newlines, other C0/DEL characters dropped, so a
  transcript can never move the cursor or paint escapes into the picker frame.
- **Native/Tern.** §7: the described sheet keeps upstream's `preview: "side"`
  and its side preview now prefers the tail-scanned `lastAnswer`; the sheet also
  advertises a `Preview` (Space) action, and a terminal without the picker kind
  gets the same content as a described card.

## 7. Tern native mode (follow-up)

The user's real terminal completes the TSP handshake, so the picker is described,
not rendered: `describe()` with `cx.supports("picker")` returns the data-first
sheet, and everything in section 2 was invisible there.

### Layout: upstream's `preview: "side"` is kept

An earlier round switched the sheet to `preview: "below"` on the theory that
Tern's narrow-pane CSS (`pv-hide`/`narrow`) hides the side column. There was no
evidence for that change and it alters the described layout at every width, so
it is reverted: `#describePicker()` declares `preview: "side"` again, exactly as
pristine 18.18.6 did, and the picker's remaining props are upstream's apart from
the Space action below. What a narrow pane does with the side column is Tern's
call (`pv-hide`/`narrow`), not something omp pre-empts by changing the layout.

### Two native paths

- **Picker kind present** (the user's Tern). The sheet advertises
  `pickerAction("preview", "Preview", "space")` only while the search query is
  empty and a session is selected; the terminal sends that action back through
  `handleNativeEvent`, and `#handlePickerEvent`'s `ev.act === "preview"` branch
  calls the same `#openPreview()` the ANSI key path uses. While the preview is
  open, `describe()` returns the preview card before the picker sheet, so the
  sheet is replaced; `Space`/`Esc` close it and the next describe equals the
  sheet from before Space, cursor and query included (the list is re-mounted
  from the same instance, never rebuilt).
- **Side-preview data.** `#describePicker()` builds its preview children through
  `#previewFor()` → `sessionPreview()`, which the patch already threads
  `lastAnswer` into (the tail-scanned newest answer, falling back to the newest
  slice of `allMessagesText`). So the side column carries the real conclusion
  without any further change; the red assertion in the previous round was not a
  data problem, it was the gate pressing a key the picker kind never receives —
  see below.
- **Picker kind absent** (a TSP terminal that draws generic cards, and the ANSI
  fallback when described): `Space` opens the same content as a described card,
  `omp.overlay.session-preview` — title, the folder/modified/size/status/model
  grid, a `Conversation` section with the first prompt in the user tone plus the
  newest answer, and `space`/`enter`/`esc` hints. `Space` or `Esc` returns to the
  described list, `Enter` resumes, `Ctrl+C` exits.
- **ANSI path unchanged**: section 2's frame-level preview still runs whenever
  `isNativeRendering()` is false.

### Headless Tern reproduction

`tern serve --control <EP> --out <dir>` runs headless on llvmpipe (software
Vulkan; no display or GPU needed) with `tree`, `dump`, `state`, `shot` (PNG +
layout JSON), `resize`, `key` and `type` on a private control socket. Two limits
found while isolating it from the user's Tern (`TERN_CONFIG_DIR`,
`TERN_DAEMON_SOCKET`, private control EP, bwrap `--unshare-net`):

- `tern serve -- ARGS` opens ARGS as tabs (`state` showed tabs titled `bin`,
  `dash`), it does not exec them; panes run `$SHELL`.
- With a `SHELL` shim execing `omp -r`, the pane program exited at once and the
  window showed "No terminals open"; `tern ctl type` text never reached a plain
  pty pane (only `Enter` produced a new prompt). Routing keys into the pane is
  the missing piece, so **no genuine native-picker PNG could be captured inside
  this budget**; none is claimed here.
- What the tree/dump capture *can* show is that a terminal pane is one canvas
  (`div.tv`): Tern's own picker/preview elements are painted inside it, so the
  layout JSON carries no picker text either. A native-path assertion therefore
  has to come from the describe output, not from Tern's DOM.

### Gate leg

Arm `native card path` in `patches/verify-session-history-preview.ts` builds the
picker through its public constructor, sets the native state, and:

1. describes with a context that supports everything **except** `picker`; Space
   must describe the first prompt and the newest answer, and a second Space must
   return to the byte-identical described list;
2. describes with a context that supports everything; the sheet must advertise
   `"id":"preview"` with `"keys":["space"]` and its side preview must carry the
   newest answer (`#previewFor()` → `sessionPreview()` with `lastAnswer`);
3. sends the advertised action the way the terminal does —
   `handleNativeEvent({ type: "action", key: "", act: "preview" })` — and requires
   the described node no longer to be a `picker` (`"k":"picker"` absent) while
   carrying the first prompt and the newest answer, then presses Space and
   requires the byte-identical sheet back.

The previous file pressed a raw Space key (`handleInput(" ")`) here. The picker
kind never receives that key — Space is the terminal's, delivered as the
advertised action — so the preview never opened and the arm was red on a check
that could not pass: it asserted `'"layout":"cards"'` was absent, but both a
picker sheet and every card node carry `layout:"cards"`. Both were fixed: drive
the public action, and assert the sheet's node kind (`"k":"picker"`) is gone.

## 8. What the user should check in Tern after install

Native mode, one omp pane, no special setup:

1. Run `/resume` (or start `omp -r`) in a project that has history. The picker
   sheet lists the sessions with their last model.
2. Leave the search box empty and select a session (arrows). Press **Space**.
   Expect the preview card: the session title, the folder / modified / size /
   status / model grid, and a `Conversation` section with the *first prompt* and
   the *newest answer* (the card replaces the sheet, it does not just scroll).
3. Press **Space** or **Esc**: the sheet must come back exactly as it was —
   same rows, same cursor on the same session, same (empty) query.
4. Press **Enter** in the preview: the session resumes into its transcript.
5. Type a few letters in the search box and press Space there: it must type a
   space in the query (`> memo z`), not open the preview.

The side column of the sheet itself (when the pane is wide enough for Tern to
show it) shows the same newest answer; in a narrow pane Tern hides that column,

**Upstream pattern and implementation.** `pi-tui/src/native/node.ts:39-46`

  there is no ANSI `SessionPreviewView`; ANSI mode retains its own windowed
