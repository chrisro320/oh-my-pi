# 自動壓縮流程與掛點（omp 18.18.0）

scout `AutoCompactionFlow` 2026-11-08 唯讀查證報告，引用以 omp 18.18.0 安裝版原始碼為準。

## Summary

- In 18.18.0 every automatic path funnels through `SessionMaintenance.runAutoCompaction(reason, willRetry, …)`; with notes-backed mode on it immediately delegates to `#runExperimentalContextRollover`, which emits `auto_compaction_start` **before** `session_before_compact` (that hook is the only extension point that can cancel).
- The existing runtime "pressure reminder" is not part of the compaction path: it is queued only when `shouldCompact()` is still false and the context is inside `[threshold − lead, threshold)`, once per reset/compaction boundary, delivered at the next aside boundary.
- An extension can cancel one automatic pass and obtain one more model turn (via `session_stop` continuation or `sendMessage`), but nothing in the runtime prevents repeated cancellation across later checks; and on the provider-overflow path a deferral is pointless.
- Manual vs automatic is not passed in the event; it is inferable only as "no `auto_compaction_start` in flight" (`manual_compaction_*` is not exposed to extensions).
- With the user's config (`thresholdPercent: 85`) headroom below the threshold is ~15% of the window (30k at 200k, 150k at 1M) — ample for one save turn, except on small windows where 85% can sit above the reserve-derived prompt budget.

## Facts

**Q1 — triggers, threshold, hook order**
- Threshold math: `promptBudgetTokens = window − max(floor(0.15·window), reserveTokens ?? 16384)` (`pi-agent-core/src/compaction/compaction.ts:349-351,365-376,411-413`, `:215`); percent override is `floor(window·pct/100)` with no reserve clamp (`:415-448`); `shouldCompact` = `contextTokens > threshold` (`:379-383`); input floored by provider usage and stored estimate (`:400-402`).
- Post-turn: `checkCompaction` (`session-maintenance.ts:3074`, decision `:3565-3566`, dispatch `:3599-3604`), invoked at `agent-session.ts:5378` (also `:5247` goal path, `:9580`).
- Pre-prompt: `runPrePromptCompactionIfNeeded` (`:2821-2892`; `shouldCompact` `:2830`, dispatch `:2880`), invoked at `agent-session.ts:9690` (and `:5542` after a revert).
- Mid-turn tool boundary: `maintainContextMidRun` (`:2898`, `:2988-3026`), invoked from the `onTurnEnd` handler at `agent-session.ts:2548`; gated by `compaction.midTurnEnabled` (`:2926`).
- Idle: `IdleMaintenance.#armCompaction/#onCompactionDue` (`idle-maintenance.ts:309-350`) → `runIdleCompaction` (`session-maintenance.ts:2204-2214`) → `runAutoCompaction("idle")`; defaults: `idleEnabled:false`, `idleThresholdTokens:200000` (`context-settings.ts:303-318`).
- Overflow / incomplete(length): `turn-recovery.ts:1315-1333` drops the failed turn then calls `runAutoCompaction(reason, true)`; call sites `session-maintenance.ts:3241` (overflow) and `:3502` (incomplete).
- `new_context`: tool just returns `details.requested` (`tools/context-notes.ts:181-195`); consumed by `takeExperimentalContextRolloverRequest` (`agent-session.ts:2970-2983`) in `maintainContextMidRun` (`session-maintenance.ts:2916-2941`) with `explicitNewContextRequest:true`; same `#runExperimentalContextRollover`, skips the fixed-context band (`:1854`) and the auto-off gate (`:5242-5243`).
- Speculative compaction: `maybeStartSpeculativeCompaction` (`:2278`); in notes-backed mode it only queues the notes reminder and returns (`:2281-2283`); otherwise skipped while a `session_before_compact` handler exists (`:2289`, `:2636`), and `deferThresholdCompactionToSpeculation` returns false in notes-backed mode (`:2383-2390`).
- Order (experimental): prepare (`:1880`) → `auto_compaction_start` (`:1889`) → `session_before_compact` (`:1906-1913`) → cancel ⇒ `auto_compaction_end{aborted:true, willRetry:false}` + `COMPACTION_CHECK_NONE` (`:1914-1922`); commit ⇒ end with result (`:2001-2017`). Classic path identical in shape (`start :5367-5368`, hook `:5596-5604`, cancel `:5605-5612`).
- Event/result shapes: `shared-events.ts:77-89` (event, no reason), `:490-494` (`cancel`, `compaction`); handlers are sequential and a `cancel` short-circuits (`extensions/runner.ts:2008-2011`); `auto_compaction_start/end` are notification-only in the extension API (`types.ts:1965-1966`); handler timeout 30 s (`runner.ts:150`).

**Q2 — runtime pressure reminder**
`#maybeQueueExperimentalNotesReminder` (`session-maintenance.ts:672-687`): requires notes-backed mode + the four tools (`:662-668`), `enabled`, not compacting, `contextTokens < threshold`, and `threshold − contextTokens ≤ lead`; `lead = clamp(12.5% of threshold, 8192…32000)` (`speculation-lead.ts:19-29`). Fires **once per boundary** (last `compaction`/`reset_boundary` entry id, `:682-685`); boundary state cleared on a committed rollover (`:1828`, `:2001`). It is queued through the host (`agent-session.ts:2984-2987`, tagged with `#promptGeneration`) and injected as a hidden `role:"custom"` message at the next aside boundary only if the generation still matches (`agent-session.ts:2652-2666`); otherwise dropped. Wording (`prompts/system/experimental-context-notes-reminder.md:2`): "The current context window is nearing its rollover threshold. … use context_notes to save a concise durable notebook … Do not call new_context until the notebook is current." It is reached only from `maybeStartSpeculativeCompaction` call sites `:2831`, `:2989`, `:3612` — i.e. only while *below* the threshold.

**Q3 — can an extension defer one automatic pass?**
Yes, mechanically: `{cancel:true}` from `session_before_compact` aborts the pass (`:1914-1922`, `:5605-5612`) and returns `COMPACTION_CHECK_NONE`, so post-turn flow continues to the stop-time passes (`agent-session.ts:5396-5450`; `session_stop` is emitted at `:5444`). A follow-up turn can be obtained by `session_stop` → `{continue:true, additionalContext}` (`types.ts:1952`, `agent-session.ts:6027-6092`, cap `SESSION_STOP_CONTINUATION_CAP = 8` at `:530,:6058`), or by `pi.sendMessage(msg,{deliverAs:"nextTurn"|"aside", triggerTurn:true})` (`types.ts:2170-2186,2429-2436`).
- Loop prevention: **none in the runtime.** A cancel is not recorded as a dead end (`#midTurnCompactionDeadEnds` only covers no-progress compactions); every later check (each tool turn, each assistant turn, each prompt) re-emits start + hook. So the extension must latch per boundary and cap deferrals itself.
- Overflow path: the failed turn is dropped, the pass runs with `willRetry=true`; on cancel the turn is restored and `retainTerminalFailure` keeps it as the outcome with no continuation (`turn-recovery.ts:1315-1333`; `session-maintenance.ts:3304-3313`). A "save" turn would replay the same over-window prefix, so the gate must fail open for `reason !== "threshold"` (and arguably `"idle"`).

**Q4 — manual vs automatic**
`SessionBeforeCompactEvent` carries no `reason`/`mode`; `preparation` exposes only `settings`, tokens, messages (`compaction.ts:1780-1815`). Automatic paths emit `auto_compaction_start` immediately before the hook (`:1889`, `:5368`); manual emits `manual_compaction_start` before the hook (`:1295-1298` → `:1398`; experimental manual `#compactExperimentalContext` hook at `:1758`), but that event is **not forwarded to extensions** (`types.ts:1965-1966`; `lifecycle-mirror.ts:184-191` maps only `auto_*`). Hence detection = latch on `auto_compaction_start`, clear on `auto_compaction_end`; no latch ⇒ manual. Caveat: an explicit `new_context` also emits `reason:"threshold"` (`:1889` via `:5247`).

**Q5 — headroom**
User config: `thresholdPercent: 85`, notes-backed on, `methodOrder: remote, soft, handoff, snapcompact`, `idleTimeoutSeconds: 300`, no `reserveTokens` (`~/.omp/agent/config.yml:87-96`). Threshold = `floor(0.85·window)`; headroom to the window = 15% (30,000 @200k, 60,000 @400k, 150,000 @1M). Default `thresholdPercent:-1` would give `window − max(15%,16384)` instead (`compaction.ts:249,411-413`). Below ~109k windows the 15% reserved prompt budget is smaller than the 85% trigger, so overflow can precede the threshold [INFERENCE from the two formulas]; one save turn (~1–3k output) otherwise fits comfortably. `keepRecentTokens` defaults to 20k (`compaction.ts:251`); the 0.8 recovery band (`:228`) applies after a commit.

**Extension source vs deployed mirror**
Repo `patches/context-notes-save-gate.ts` = 338 lines, mirror `~/.omp/agent/extensions/context-notes-save-gate.ts` = 300. Hooks, reminder, ack and retention logic are identical (`tool_call:263`, `tool_result:275`, `turn_end:311-322`, `before_agent_start:327-336`; mirror `:263-…`). Differences are all in `parseIndex`: the mirror (mirror `:82-108`) requires exactly four top-level keys (`Object.keys(index).length !== 4`) and a present `supersedes` array; it has no `describe()` helper, no `INDEX_KEYS` whitelist, no per-row unknown-key or `supersedes` nonempty/uniqueness checks and coarser messages. The repo (`:88-171`) adds `describe()` (cycle-safe rendering, `:76-86`), explicit version check, unknown-key listing, omitted `supersedes → []`, and per-field validation. Net: mirror is the older, stricter-but-less-diagnostic copy; a notebook omitting `supersedes` is accepted by the repo and rejected by the mirror.

## Feasible designs

1. **Extension-only gate (no runtime patch).** In `session_before_compact`: skip unless the `auto_compaction_start` latch says automatic and `reason === "threshold"`; skip if a `new_context` tool result with `details.requested === true` is the tail of `branchEntries`; skip if a `context_notes` entry + receipt exists after the current compaction/reset boundary. Otherwise `{cancel:true}`, latch `boundaryId → deferred`, and inject a save instruction (`deliverAs:"aside"` mid-run, `nextTurn`/`triggerTurn` at a terminal stop, or `session_stop {continue:true}`). Risks: registering the hook disables classic speculation and the grace band while loaded (`:2289,:2386,:2636`), contradicting the verifier invariant "registers no `session_before_compact` handler" (`patches/verify-context-notes-save-gate.ts:7`) and the 2026-10-23 decision; no phase in the event means pre-prompt vs post-turn is indistinguishable; `new_context` detection is heuristic; no runtime loop guard; `context_notes` writes may not yet be in the branch at a mid-turn cancel.
2. **Runtime patch in `#runExperimentalContextRollover`.** Before emitting start (or just after the hook), if `reason === "threshold"` and `!options.explicitNewContextRequest` and no note exists in this window, skip the commit, queue the reminder + a continuation with a per-boundary one-shot flag. Precise reason/new_context knowledge, manual `/compact` (`#compactExperimentalContext`, `:1739`) untouched. Risks: patch-family regeneration/version skew; changes to the family the gate-removal rebuilt.
3. **Hardening only** (earlier reminder, stronger wording): zero veto risk but no guarantee — a rollover can still occur with a stale notebook.

## Unknowns

- Whether `ctx.isIdle()`/queued-input state can reliably distinguish the pre-prompt check from post-turn (no phase field on `auto_compaction_start`).
- Whether a cancelled pass at pre-prompt leaves the user prompt going out over-threshold (code path returns then dispatches at `agent-session.ts:9690`; not exercised).
- Whether `branchEntries` at a mid-turn hook already contains the just-finished turn's `context_notes` result (persistence runs behind `persistTurnMessagesForMidRunCompaction`, `:2931`).
- Real-SDK behavior of `session_stop` continuation combined with an immediate second automatic check (not run in this read-only investigation).
