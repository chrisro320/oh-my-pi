# Subagent worker threads (`task.workerThreads`) vs our patch set — 18.18.0

Author: WorkerThreadsDesign. Scope: make worker mode ON work with our 24 patch families (0065/0025/0100 retired). Turning it off is only a fallback and needs a failing gate.

Notation. `T18` = `~/.cache/omp-plan-18180/18.18.0/nm/@oh-my-pi/pi-coding-agent/src/`; `U18` = same tree, `pi-utils/src/`. `P:<family>:<line>` = line in `patches/.18.16.0-families/family-<family>-v18.16.0.patch`. `[INFERENCE]` = not observed, derived. Probes marked `[PROBE]` were throwaway `bun -e` runs in /tmp (Bun 1.4.4), no repo/state touched.

## 0. Headline findings

1. **Worker mode is inert below 9 concurrent subagents.** `SUBAGENT_WORKER_THRESHOLD = 9` (`T18 thread/subagent-worker.ts:57`; raised from the 18.17.0 value by upstream `4b047744f9`). `allowedSubagentWorkers` returns 0 for < 9 concurrent runs, 1 for [9,18), 2 for [18,36)… capped at `task.workerThreads` (`subagent-worker.ts:64-72`). With ≤ 8 concurrent subagents everything runs on the main thread, identical to `workerThreads=0`. The user's config does not set `task.workerThreads` (default 4, `T18 task/settings.ts:438-458`), so ON is already the effective mode for our installed omp; only fan-outs of ≥ 9 are affected. Every gate we have today is blind to worker mode (none builds a pool; they call `runSubprocess` with no pool), so "gates green" says nothing about it.
2. **Auth is single-owner on main by construction** (so the refresh-token race the user fears cannot happen at the worker boundary), **but our 0090 patch adds two `OAuthApi` methods (`inspectUnresolvedRefresh`, `unlockAndRefreshStored`) that `RemoteOAuth` does not implement.** The patched preflight in `agent-session.ts` calls the first one on a missing-key path; in a worker-homed session that is a `TypeError` (crash class) instead of the `/auth-unlock` message. Needs a RemoteOAuth + `AuthStorageProtocol` addition served by main.
3. **Process-global state is duplicated per thread.** Confirmed `[PROBE]`: a worker sees the OS environment of process start; it does NOT see `process.env` writes the parent made at runtime, and the parent does not see the worker's writes. This breaks (a) `PI_CACHE_WARMING_IDLE_MAX_MS` writes (harmless today: no warmer in workers), (b) `setProfile/setAgentDir` runtime env writes (`U18 dirs.ts:559-567,597-628`) — a worker re-enters `runCli`, finds no `--profile`, and resolves from the OS env only (`T18 cli.ts:477-491`). **[INFERENCE]** a `--profile X` omp run would place its ≥9-fanout workers on the *default* agent dir (agent.db, auth, sessions) unless `OMP_PROFILE`/`PI_CODING_AGENT_DIR` is in the OS env. Our deployment doesn't pass `--profile` (not seen in config), but this is the one real "wrong database" hazard; make it an experiment (Q3).
4. **0101 warm revival degrades silently to cold persisted revival when a worker is reaped** (60 s idle, `DEFAULT_IDLE_MS`, `subagent-worker.ts:49`) or dies. The cold path reuses the persisted system prompt but rebuilds tools/MCP view; byte-equality of the first post-revival request prefix is unproven. Class: cache-prefix loss. Gate leg: forced-worker revival, compare system+tools bytes and cache-read ratio.
5. **Most companions are per-instance module state and therefore per-worker.** Only concrete finding: `payload-archive.ts` filename (`Date.now()-pid-seq`) can collide across threads (threads share `process.pid`, each instance starts `seq` at 0). Diagnostic loss only.

### 1.2 Settings and placement
- `cfgTaskWorkerThreads`: `protocolDefault ["rpc","acp"]`, default 4, non-negative integer, read live on each placement (`task/settings.ts:438-458`).
- `allowedSubagentWorkers` (`subagent-worker.ts:64-72`); `place()` 391-396; `#select()` 488-505: fewest-runs worker wins; ties → existing worker over main, main over starting a new worker. Resident holds (`retain()`) keep the worker alive but do NOT count toward placement (213-220).
- Pool factory `subagentWorkerPool` (561-587) requires `isMainThread()`, `workerHostEntry() !== null`, `workerThreads > 0`. Prewarm (596-601) is fired from `session/agent-session.ts:4613` when a streaming spawn call is seen (`#spawnSignal` 1271, main only).
- Idle shutdown `DEFAULT_IDLE_MS = 60_000` (`subagent-worker.ts:49`); init timeout 30 s (41).
- Worker host: `spawnBunWorker` re-enters the CLI entry with argv `SUBAGENT_WORKER_ARG` (`subagent-worker.ts:103-109`); `cli.ts:528` `if (isProcessEntry) declareWorkerHostEntry()`; `cli.ts:255-259` installs inbox then imports `thread/subagent-worker-entry`. Our launcher does `execve bun cli.ts` (`patches/release-launcher.py:143-145`) so it is a process entry → host available. Spawn passes no `env` option (`subagent-worker.ts:107`).
- Test seams: `setSubagentWorkerPoolForTests(pool)` (612-615), `SubagentWorkerPoolOptions.hostsOnMain:false` (342-346), `entry: URL` to bypass the CLI host (82-83, 104). Upstream smoke: `smokeTestSubagentWorker` (617-630) via `cli.ts:162,191`.

### 1.3 Boot
`SubagentWorker.#start` (237-286): `installMain` per thread service, init message (threadId + replyPort + SharedArrayBuffer counter), then `boot` with service `globals`. Worker side `thread/subagent-worker-entry.ts:20-31` log forwarding + `installGlobalProxyFetch()`; 65-87 installs every service's `installWorker`, handles `boot`/`ping`/`warmUp`. `#die` (300-323) closes the link and runs `onWorkerExit` per service. Service order (`thread/services/index.ts:21-37`): identity, logger, runtime-identity, settings, auth, agents, lsp, telemetry, memory, integrations, runtime, async-jobs, executor. Warm-up session uses `disableExtensionDiscovery:true`, MCP/LSP/IRC off, `cacheWarming:false` (`thread/worker-warm-up.ts:47-63`).

### 1.4 What runs in a worker
- The whole subagent run: `task/executor.ts:4383-4386` `runSubprocess` → `runSubprocessPlaced` (`thread/executor-routing.ts:127-153`) → `worker.link.call("runSubprocess", request)` → `runSubagentRunRequest` (`executor.ts:4403`) → `runSubprocessOnThisThread` (4413). That builds a full `AgentSession` in the worker (`createAgentSession`): provider streaming, tool execution, its own `ExtensionRunner`, its own `SessionManager` (JSONL writer opened in the worker), context/compaction/audit hooks. Main holds a `RemoteAgentSession` mirror (`thread/services/agents.ts:106-120`, `session-publisher.ts`).
- Follow-ups go to the home thread (`runFollowUpTurnOnHome`, `executor-routing.ts:174-199`). Cold revival is placed like a fresh spawn: `revivePersistedPlaced` (205-219) → worker-side `revivePersistedSubagent` (`task/persisted-revive.ts:251-568`).
- Nested spawns from inside a worker stay in that worker (`executor.ts:4384`).
- Worker death: main detaches refs and marks them `parked` (with sessionFile) or `aborted` (`agents.ts:192-214`); run result becomes `lostRunResult`.
- Subagent session options force `cacheWarming:false` (`executor.ts:4944-4945`); `CacheWarmer` is created per session at `sdk.ts:4808-4816` → **no warmer ever runs in a worker**.
- `IdleMaintenance` (`session/idle-maintenance.ts`) is enabled only by the interactive owner UI (`modes/interactive-mode.ts:1906`); remote sessions forward to the home worker (`remote-agent-session.ts:804-816`, `session-publisher.ts:627-628`). In practice main-session only.

### 1.5 What crosses the MessagePort (`thread/rpc.ts`)
- Structured clone; functions become remote callables (`rpcSync` = worker→main synchronous via SharedArrayBuffer + reply port); AbortSignal mirrored; Errors rebuilt by registered name (`rpc.ts:182`); classes cross as references (`exportClass`/`importClass`); codecs for session, ref, settings, prepared-extension, local-protocol-options, tool-context; any other class instance is refused with `RpcEncodeError` (`rpc.ts:29-36`).
- **By reference to main singletons**: `AuthStorage` (`services/auth.ts:4-7,456-460`; `RemoteAuthStorageBackend` `auth-remote.ts:633-672`; `replaceStore` refused 663-667, `close` no-op); `ModelRegistry` is a worker-local mirror following main change batches (`auth.ts:8-22,382-397`), custom `streamSimple` runs on main (`streamOnMain`, mirror `model-registry-mirror.ts:219-239`), OAuth `getApiKey`/`modifyModels` are `rpcSync` on main; slow-mode lanes (`auth.ts:23-25,509`); `AgentRegistry`/`AgentLifecycleManager`/`IrcBus` (`agents.ts:1-22,336-350`); Settings mirror with main as sole writer (`services/settings.ts` header; `getStorage()` = main's agent.db handle); cost-gate, event-bus, artifact-manager (ids on main), agent-storage (`services/runtime.ts:1-32`); AsyncJobManager; MCPManager (`RemoteMCPManager`, tools as views, `execute` on main; a worker never connects MCP, `sdk.ts:2832-2833`); Hindsight client/state (`services/memory.ts`, `memory-remote.ts`); LSP shared-mode; telemetry; logger records.
- **Extensions**: `PreparedExtension` crosses as module path; the worker re-imports and runs the factory against its own `ExtensionAPI` (`services/integrations.ts:16-20,211-275`, `threadLocalFactory` 234-245). Parent-bound extensions rebound via `preloadedPreparedExtensions` (`sdk.ts:2997-3030`; `executor.ts:4959-4962`); options bridged by `bridgeIntegrationOptions` (`integrations.ts:129-144`). Extension-registered model providers in a worker are dropped; the mirror follows main's.

## 3. Gate design summary (offline, bwrap)

1. **Common fixture**: `workerPoolForTests` helper that builds a `SubagentWorkerPool` with `hostsOnMain:false` and a test `entry` URL (patterned on upstream `test/thread/subagent-worker.test.ts`, `test/fixtures/integrations-worker.ts`, `test/fixtures/model-registry-mirror-worker.ts`), registered with `setSubagentWorkerPoolForTests`. Run each existing gate twice (pool=null vs forced-worker) and diff observables.
2. **Observables**: (i) request count on one transport (0092, 0010); (ii) system+tools byte equality + cache-read ratio on first post-revival request (0101); (iii) refresh-token single use + token-POST count (0090); (iv) hook payload equality (0095, 0083).
3. **Mutation controls**: each leg must turn red when the invariant is broken (e.g. give the worker session a warmer; skip persisted tools replay; delete `RemoteOAuth.inspectUnresolvedRefresh`).
4. **Fallback gate**: if any leg cannot be made green, the fallback is `task.workerThreads: 0` in the shipped default settings (or raising the gate to never place), and the failing leg stays as the documented evidence. Do not simply set 0 first.
5. **Gate wiring**: new gates go into `_omp_run_gates` (`patches/apply.sh:492-619`) after the existing 0010/0090/0092/0101 groups.
